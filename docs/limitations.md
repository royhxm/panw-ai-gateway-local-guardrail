# 已知限制与安全边界

## 分类与误报

本项目中的 Qwen3Guard-Gen-0.6B 是生成式内容安全分类模型，不是完整的网络防火墙、
身份验证系统或保证覆盖的提示注入检测器。CPU INT8 分类存在误判和漏检。
实际实验中，直接越狱可能被标为 Controversial / Jailbreak；一些间接注入会被判 Safe，
纯数字也曾被误判为不安全。提示词轻微变化就可能改变分类。

本仓库不发布一个有代表性的检测率指标，也不将少量 smoke test 通过率作为安全覆盖率。
需要自行建立业务评估集，分别度量误报、漏报、语言、历史长度及量化带来的变化。
不存在“测试几条恶意提示后就能保证安全”的结论。

## PII 覆盖

当前只实现以下识别器：

- CN_PHONE_NUMBER：连续 11 位大陆手机号，支持部分 +86 前缀；不支持所有空格/连字符变体。
- CN_ID_CARD：18 位、日期合法且校验码匹配；不能证明证件真实存在或属于某人。
- EMAIL_ADDRESS：正则格式匹配；不能证明邮箱存在。

spaCy 使用空白中英文管线，没有加载通用姓名/地址 NER。不要声称已提供完整中文 DLP。
示例号码和证件仅为格式测试，不应用于联系、身份验证或真实业务。

## 历史、角色和工具

全部传入消息文本参与输入检查，日志摘要仅显示最后一个 user。历史中包含助手生成的
示例手机号，也可能引发阻断。模型分类当前使用拼接文本，不保留业务模型的全部角色语义。

角色化日志是观测功能，不代表完整支持工具调用、多模态输入、任意 Responses API
结构或原始代理流量。图片/音频拒绝；不支持的无文本工具消息应视为未支持。

## 流式

before hook 能在生成前检查完整输入。当前不是 Qwen3Guard-Stream，不做增量 token
分类。after hook 是否触发及能否见到完整响应由网关实现决定。即使最后一次检查阻断，
已经送达客户端的流式内容无法撤回。严格输出防护需要非流式或网关缓冲。

## 日志不是端到端抓包

`request.json` 是网关提交给检查器时的快照，不是客户端原始 HTTP 的证明。
`verdict:true` 是检查判定，不是 LLM 已接收的确认。`response.json` 是网关回传的
输出阶段快照，不证明客户端实际收到相同内容。没有这些证据时页面明确显示未观测。

元数据的 feature、model、usage、isTransformed 等只是网关上报的值，不做真实性认证。
同一 Trace ID 被重用时可能有多次重试；不能把相同 session_id 的标题生成与聊天混配。

## 部署与凭据

默认只监听回环地址，不自动开放公网。host 网络不提供独立容器网络隔离；本机进程可以
访问内部模型和 PII 服务。只在受信任的 Linux 主机部署，保持内部服务回环监听。
跨主机访问按环境配置 TLS、私有路由和现有安全策略。

设置两个独立的随机 Token，不复用 Linux、GitHub 或业务 Provider 密码。`.env` 应为
0600，不应进入备份发布包或 Git 历史。不要将 Authorization 通过 Forward Headers 转发。
SSRF 受限的网关只能按审批追加准确的目标主机，不应禁用 SSRF 检查。

日志遮盖的是 Presidio **检出的**内容，并非加密或全面匿名化。未识别的 PII、商业信息、
提示词和模型输出仍可能被保存。使用日志前评估数据最小化、保留期和访问要求。
SQLite 为本地明文数据库；没有多租户权限隔离。不要公开发布真实运行数据库、请求快照、
截图或日志结果。当前 UI 也不提供原始 PII 的还原能力。

## 资源与故障

一次只执行一个模型推理，最多四个请求获准执行/等待，锁等待上限 60 秒。模型请求
的 Webhook HTTP timeout 为 90 秒；网关示例超时为 95 秒。高并发、长输入、内存压力、
依赖失败或日志磁盘满均需要监控和容量规划。

模型上下文 4096 tokens，生成上限 96 tokens，输入文本最多 12000 字符。不静默截断。
依赖异常返回 503。必须在网关启用 deny 和 failOnError 才能实施故障阻断。
结构化日志增强失败不影响已经产生的 verdict；日志持久化失败写入容器错误日志，
当前健康检查不保证审计磁盘可写或记录完整。
